# RoamReady AI — Judge Readiness

## Core proposition
RoamReady plans trips and adapts them when conditions change, explaining
the impact on budget, travel time, preferences, and itinerary quality.

## Judging dimension: Tech Implementation
- [ ] MCP endpoint and transport verified against current Alexa+ rules
- [ ] Existing tools execute and return structured results
- [ ] Inputs are validated and errors are handled safely
- [ ] Provider failures have reproducible tests
- [ ] Demo works without paid API credentials
- [ ] Tests and local setup are reproducible

## Judging dimension: Design
- [ ] A first-time user can start a demo without instructions
- [ ] Plan, disruption, rescue, comparison, and save are easy to find
- [ ] Before/after differences are visually clear
- [ ] Loading, empty, error, and success states are implemented
- [ ] Mobile layout and keyboard accessibility are checked

## Judging dimension: Potential Impact
- [ ] Target user and travel disruption problem are clearly explained
- [ ] Budget and time trade-offs are quantified from actual itinerary data
- [ ] Limitations and simulated data are disclosed
- [ ] Benefits are supported by a reproducible example

## Judging dimension: Quality of Idea
- [ ] The demo shows multi-step recovery, not just a single-turn chatbot
- [ ] User preferences persist and can be changed or deleted
- [ ] Rescue decisions explain their reasoning
- [ ] Structured results support a multimodal experience

## Submission package
- [ ] Public code repository and visible license
- [ ] Demo video under three minutes
- [ ] Accurate README and setup instructions
- [ ] Product feedback for every tool, API, and SDK used
- [ ] Significant changes made during the hackathon are explained
- [ ] Any friction log contains genuine, reproducible observations
- [ ] Final deployment and repository links verified

Do not mark an item complete until it has been checked.
